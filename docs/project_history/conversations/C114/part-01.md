### Root cause

The M2.8 retry-settlement amount used the following rounding order:

```text
ROUND(
  ROUND(exposure / duration, 2)
  × payment_factor
  × retry_multiplier,
  2
)
```

For the affected account:

```text
ROUND(4699.37 / 14, 2) = 335.67

Scheduled event:
ROUND(335.67 × 0.75, 2) = 251.75

R12 retry event:
ROUND(335.67 × 0.75 × 2, 2) = 503.51
```

The retry calculation multiplied the unrounded factor result before applying the final cent rounding. The corrected calculation rounds the scheduled cent amount first:

```text
ROUND(
  ROUND(
    ROUND(exposure / duration, 2)
    × payment_factor,
    2
  )
  × retry_multiplier,
  2
)
```

That produces:

```text
ROUND(251.75 × 2, 2) = 503.50
```

The seven-event processed total then becomes exactly `$1,762.25`, restoring:

```text
processed = scheduled − returned + retry
```

and the correct ending exposure of `$2,937.12`.
