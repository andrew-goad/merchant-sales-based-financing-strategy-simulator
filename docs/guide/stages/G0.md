# G0 · Physical data foundation

**What has to be true before any merchant evidence can be generated?**

[Stage map](../../README.md#stage-map) · [Which source version?](../SOURCE_VERSIONS.md) · [Current use](../CURRENT_USE.md)

> **Source basis:** original `v0.2_ACCEPTED` in `Module_0/0.01_G0_Physical_Data_Foundation`. This is the retained foundation/Module 1 basis; no Module 1 technical payload is changed by the R26 successor. This is a reading companion, not a new technical acceptance or execution guide.

A controlled financing analysis needs more than a set of populated tables. It needs a place to record **what each row means, which configuration produced it, and which boundaries must hold before the next stage starts**. G0 supplies that physical foundation; it does not supply the merchant population or credit decisions.

## A schema and seed—not a portfolio

The accepted foundation separates project schemas, parent tables, partition children, constraints, reference data and evidence objects. Its baseline contains **70 designed parent/non-child tables and 1,041 designed columns**, plus four child partitions. The 74 physical table relations are not 74 independent business entities. Later controlled extensions do not retroactively change the G0 baseline counts.

The source guide records eight schemas, five views, three functions, 155 parameter definitions, one initial parameter set and 397 values. Those parameters define a governed starting point; they are not empirical estimates of lender behavior. Merchant, application, latest and archive populations are empty at this gate.

## Read the physical controls in context

| Foundation element | What it establishes |
| --- | --- |
| Schema and parent-table definitions | Named objects, data types, required fields and physical keys before generation. |
| Primary and foreign keys | Referential obligations between identities—not proof that future analytical values are correct. |
| Reference and parameter seed | A versioned configuration vocabulary and initial values. |
| Validation SQL and exported result | The actually observed catalog/seed/empty-state comparison. |

The catalog distinction has a concrete implementation consequence. `pg_inherits` includes partitioned-index inheritance as well as table inheritance. The accepted validation restricts child-table counts to `pg_class.relkind = 'r'`. Counting every inherited relation would conflate indexes with business tables and falsely change the physical milestone.

## Handoff to governed run control

G0 creates the structures that G1 will use to resolve and freeze a run. **A schema existing is not the same as a run being ready.** G1 must select configuration, resolve ambiguity, bind source contracts and establish the immutable snapshot identities before merchant generation.

The original execution guide is a historical stage procedure, not a current empty-database R26 Quickstart. It records PostgreSQL 17.9 on Windows for G0. That environment observation does not qualify an end-to-end rebuild of every later revision. Use the Current Use Guide to distinguish source study from the separately qualified checkpoint route.

## Requirements interpretation

The following are editorial reading locators into the retained requirements/design/authority documents—not invented native requirement IDs. Native IDs and control lists remain in the linked originals.

**Live guide · Accepted structural values.** Separate designed parent objects, child partitions and view columns instead of promoting a catalog total to a business population.

**Live guide · Important catalog rule.** Use the table-only partition test; the corrected SQL is the source, not a newly proposed check.

**Package report · Source and evidence validation.** Retain schema/seed identity, empty analytical state and the actual accepted milestone together.

## What the retained validation establishes

The retained G0 package report records a passed physical milestone, zero static DDL errors/warnings, and a live CSV matching all 24 specified environment, object, constraint, seed and empty-state values. The report also records repeatable seeding. This guide reads that evidence; it does not execute the schema or reproduce those database tests.
