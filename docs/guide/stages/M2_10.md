## Analytics after reconciliation

M2.10 consumes certified account state and source lifecycle evidence to create portfolio-performance and servicing analytics. It must explain the number rather than make an aggregate appear more conclusive than its inputs.

The account-level population is 130 funded scenario paths, not all 1,500 application-scenario decisions. The Baseline and Recession Energy subsets remain distinct. Authorization rates use the application denominator; payoff and servicing measures use the relevant funded/account denominator. One percentage cannot silently stand in for the other.

## The endpoint has three different meanings

The accepted successor's connected operating evidence contains 126 closed/no-further-action paths, three review holds and one active, reconciled path. The retained performance result carries **$6,061.03** of certified ending exposure after the $1,762.25 servicing bridge from $7,823.28 monitoring-end exposure.

“Reconciled” means that the source and ledger agree. It does not mean “paid off.” “Review held” means processing permission remains withheld. It does not mean the recommended action occurred. These are useful distinctions for both a credit manager and a reviewer checking the underlying contract.

## Calculate only when the basis exists

The physical KPI logic separates valid denominators from non-applicable calculations. Do not replace a zero or absent denominator with an invented percentage. Likewise, monetary totals must retain their stage and scenario: principal advanced, total repayment, monitoring remittance, post-monitoring servicing and certified residual are related but different amounts.

Modeled risk-adjusted contribution is not audited realized profit. Comparative expected loss is not CECL. The current documentation preserves those interpretation boundaries while still showing the financial reasoning and account-to-portfolio link.

## What was corrected in the successor

The change-control report identifies brittle exact-dollar status mapping in predecessor analytics. The successor uses actual account-state and reconciliation semantics instead of deciding a status from a particular expected dollar signature.

R26's upstream monitoring calibration does not change the final M2.10 business output: 130 rows, 19 shared columns and zero different cells versus R17. The original v0.2R5 acceptance's 59-path figures remain archived, not promoted to the current landing page.

## The analytical handoff

M2.11 evaluates bounded alternative strategy profiles using the accepted source population; M2.12 certifies source consumption. Power BI P01/P02 present portfolio/lifecycle questions, P03 connects application evidence to decision and account context, and P04 exposes servicing/certification detail.

G3-v2 source certification precedes consumption. Power BI's separate acceptance addresses the actual report implementation, bindings and behavior. Neither a dashboard screenshot nor a source-certification count should be used as a replacement for the other's evidence.

A useful reading exercise is to start at a portfolio residual, identify its scenario, find the account states that contribute to it, and return to the event and reconciliation records. That is a traceable analytical explanation—not a chart-only claim.
