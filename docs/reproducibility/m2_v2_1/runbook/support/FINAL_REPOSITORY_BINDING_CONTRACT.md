# Final repository and clean-start binding contract

**PUB-RUN-001 / R1 — OPEN finalization requirements, not a new execution grant.**

## Required final-plan fields

Each normal step must have: sequence; stage; program ID; exact repository-relative path; SHA-256; input/target database identity; required predecessor state; self-managed versus read-only transaction behavior; session requirement; command adapter; expected checkpoint query and comparator; output/evidence path; failure rule; and approval basis.

Resolve source by accepted authority and exact bytes. Never choose the newest filename, silently substitute a recovery program, sort a directory of SQL, or execute the 230-row historical catalog as the R26 successor. The provided historical hash map is a diagnostic reading aid. A missing historical hash in the inspected R23 tree is not proof that the accepted engine is defective or that no later replacement exists.

## Bootstrap choice that must be made explicit

The publication owner must provide either (a) the qualified full generation chain from a truly empty approved database, including all seed inputs and selected clean-build sources, or (b) a clearly labeled checkpoint-based route with a public-safe seed/backup carrier, a tested restore procedure, declared prerequisites and a truthful statement that earlier stages are restored rather than recomputed. A checkpoint route must never be marketed as independent re-execution of all prior SQL.

A complete database restore needs source format/version, compression, byte hash, role/ownership assumptions, encoding/collation, object/extension inventory, protected-source identities, allowed target rules, and a post-restore reconciliation. No such restore carrier is invented or generated here. Output CSV exports are not sufficient to infer functions, constraints, control state or accepted database OIDs.

## Qualification

An independent control party follows the exact documented path on the approved Windows environment, records software, target identity, commands, outputs and failures, and compares all applicable gates. A qualified offline Route A does not close a database Route D claim. Historical source-owner runtime acceptance does not automatically prove this new runbook is self-contained for an unfamiliar operator.

Integrate the final paths and locks into the next runbook revision. If new source changes are necessary, keep them separate from this documentation delivery, test them under appropriate source authority, and carry their actual evidence. No R26/PBIX rerun is required solely to update a documentation path.
