Recalculate the exhibits

From the repository root, run these commands with Python 3.11 or later. The checks use the included extracts and the Python standard library.

python -B research-site/evidence/verify_studies.py
python -B research-site/evidence/check_readme_table.py

The first command checks the CSV digests and scenario aggregates. For Local Take 4 and the two larger studies it reconciles the financing decisions and day-120 contractual receivables, and recalculates the daily payments in each featured trace. It also checks the decision transition counts, the earlier payoff example, the counteroffer counts and the recorded durations. The second checks the repository’s comparison and the five interactive studies against the same extracts. It verifies Baseline and Recession Energy separately in each funding table, including principal and supportable share, and checks the decisions and monitoring totals at the top of each study. Choose the right denominator

Question Records to inspect
How did the policy classify all applicants? The seven decision categories sum to the size of each cohort in each scenario. The 750 rows in this file cover Local Take 4. A supportable path includes either authorization or a referral for review. Only the two authorization categories funded in these studies.
Where did the same applicant go under stress? The matched decisions cross authorization, review and decline. The last column counts changes among the seven detailed categories, including a counteroffer replacing an approval for the full request. The totals are 241 of 750 in the Local Take 4 rehearsal, 822 of 2,500 and 8,163 of 25,000.
Which merchants received financing in each scenario? For Local 750, compare all paired decisions and closing balances with issued principal. The 2,500 and 25,000 extracts include each merchant funded in at least one scenario.
How many still owed money after 120 days? A positive closing contractual receivable counts as open. A zero balance records payoff. A blank scenario balance denotes an application that received no financing in that scenario. Restrict both sides to merchants funded twice to compare the same borrowers.

Interpreting computation time

The Local 750 clock covers native financial execution. The 45-minute AWS timing comes from a separate 750 rehearsal. Both are timing guides for the original DBeaver workflow. For 2,500, the 2 h 24 min sums two module receipts from different executions. The displayed m7i.4xlarge is the reference configuration. The Module 1 receipt identifies m7i-flex.large, and the Module 2 receipt leaves the instance type unspecified. The 25,000 campaign recorded 15 h 26 min of computation.
